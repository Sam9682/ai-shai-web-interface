# Jira `SOV-856` — `[MS2][Dedicated Keystone] Development`

> Parent: `LVL2-18375`. User-story Epic: `SOV-850`.
> **Blocked by `SOV-865` (OSQ-17 — secrets handoff) and `SOV-866` (OSQ-02 — Keystone topology).**

## Scope

* Deploy a **dedicated Keystone instance inside the OS Package** via the SOV-254 Keystone Controller
* Federate to the **CloudStore Keycloak** (same Keycloak↔Keystone federation pattern as CB)
* Wire RGW to Keystone using 6 config params (confirmed by Ibrahim 2026-05-27):
  `rgw_keystone_url`, `rgw_keystone_api_version`, `rgw_keystone_admin_user`, `rgw_keystone_admin_password`, `rgw_keystone_admin_project`, `rgw_keystone_accepted_roles`
* RGW admin user created in Keystone at service-enable time
* Handle secrets handoff (OSQ-17): how admin user/password generated by Keystone Controller flows into RGW config

## SNC consideration (M3 prerequisite)

SNC requires admin/user audience separation (2-Keystone model): one Keystone for S3 users, one for S3 admins. The exact topology (single vs dual for M2 beta) is OSQ-02 — needs the dedicated meeting (Florent + Vincent + Ibrahim). M2 may ship with single Keystone (beta); dual-Keystone upgrade lands in M3.

## Dependencies

* `SOV-864` OSQ-15: if Rook wins, k8s Secrets in `oss-cp` are the natural answer for OSQ-17
* `SOV-865` OSQ-17: secrets handoff must be decided before RGW config wiring can be finalised
* `SOV-866` OSQ-02: Keystone topology for SNC
* SOV-254 Keystone Controller (Ibrahim Takouna) — confirmed compatible for both CB + OS
